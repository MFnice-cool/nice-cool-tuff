# Спринт 2 — Release Readiness: блокеры публичного релиза

Дата: 2026-09-11
Ветка: `arena/01a08f1a-tuffbox-build-test`
Задача: выявить ключевые недостатки, не позволяющие выпустить TuffBox в общий доступ, выбрать важнейшие и разработать их.

---

## Карта анализа

Проверены: безопасность файлов/архивов (все места распаковки zip), секреты (приложение + Supabase-миграции), отказоустойчивость рантайма (panic-поверхность: mutex-poison, LazyLock-билдеры), CI-конвейер выпуска (что происходит между «красными тестами» и рассылаемым exe), лицензионная база, поверхность атаки webview, first-run UX (AI-онбординг уже прикрыт модалкой Settings → AI из спринта диагностики).

## Найденные блокеры и что сделано

### 🔴 SEC-1. Zip-slip: произвольная запись файлов при импорте CurseForge-паков — ИСПРАВЛЕНО

`crates/tuffbox-core/src/importer.rs::extract_curseforge_overrides`. Запись вида `overrides/../escaped.txt` проходит проверку префикса и записывается **за пределы каталога проекта** — классический path traversal. Пак .zip — недоверенный вход (сторонние зеркала, ручные сборки, обмен паками): это вектор произвольной перезаписи файлов на машине пользователя.

**Сделано:**
- добавлен `is_unsafe_zip_rel_path()` (сегменты `..`, абсолютные пути, `C:/`, UNC) + отказ импорта с `ImportError::PathTraversal`;
- tests: malicious-пак с точной целью побега (файл не появляется), таблица опасных/безопасных путей, регресс на легитимном паке (2 файла, `manifest.json` не экстрактится).

### 🔴 SEC-2. Хрупкая проверка zip при восстановлении бэкапа — ИСПРАВЛЕНО

`apps/.../lib.rs::restore_backup`. Старая проверка `canonicalize(target)` ложко-отбрасывала **легитимные** записи в новых подпапках (нечего канонизировать до создания родителей) → restore падал на нормальных архивах; при этом логика полагалась на порядок create/canonicalize. 

**Сделано:** лексический guard через тот же `is_unsafe_zip_rel_path` + создание родителей + канонизационная проверка как defense-in-depth. Restore снова работает для новых подпапок и отклоняет побег.

### 🔴 SEC-3. Скомпрометированный moderation-секрет в публичной миграции — РОТАЦИЯ ДОБАВЛЕНА

`supabase/migrations/015_security_hardening.sql` хардкодит секрет модерации (`UPDATE admin_config SET value='MFCOOL'`). Репозиторий публичный ⇒ **любой читатель держит админ-креденшал community-базы** (удаление/одобрение капсул, модерация). Приложение сам секрет не содержит (проверено) — ротация ничего не ломает у пользователей.

**Сделано:** миграция `020_rotate_moderation_secret.sql`:
- очищает слабые/известно-скомпрометированные значения (<16 символов, `mfcool` и типовые);
- `_admin_secret_ok` ужесточён до ≥16 символов и вечно отвергает `mfcool` (fail-closed);
- runbook для ops в шапке миграции: выставить сильный секрет out-of-band **до релиза**.

### 🟠 CRASH-4. Panic-поверхность: poisoned locks и LazyLock-паники — ИСПРАВЛЕНО

Одна паника под глобальным мьютексом навсегда «кирпичила» приложение: каждый следующий захват глобального кэша/прерывателя падал (`expect("lock poisoned")`), осыпая несвязанные фичи. Пользователь-не-технарь видит только «программа сломалась до перезапуска».

**Сделано** (паттерн уже использовался в `process.rs` — распространён на все глобальные локи):
- `api_cache.rs` (8 локов) — diagnoses/health/AI-context кэш: `unwrap_or_else(|e| e.into_inner())`;
- `http.rs` circuit breaker (3) — отказ сетевых пауз больше не каскадируется;
- `mod_files.rs` (2) — потоковая запись отчётов;
- `http.rs` билдеры клиентов — `.expect("Failed to build HTTP client")` заменён на fallback к простому клиенту (экзотический TLS-конфиг больше не паникует процесс на первом сетевом вызове).

### 🟠 CI-5. Рассылаемый exe собирался без прогона тестов — ПАТЧ ДЛЯ ВЛАДЕЛЬЦА

`build-windows.yml` — единственный конвейер, собирающий бинарник для скачивания, — не запускал `cargo test`: красные тесты не мешали появлению артефакта.

**Сделано:** готовый патч `docs/patches/0001-build-windows-release-test-gate.patch`
(шаг `cargo test --workspace` как release-gate перед `tauri build`). Применить:
`git apply docs/patches/0001-build-windows-release-test-gate.patch` и закоммитить
аккаунтом с `workflows`-пермиссией (токен агента менять workflow не может — push
был отклонён GitHub именно по этой причине).

### 🟠 LEGAL-6. Объявленная двойная лицензия без текстов лицензий — ИСПРАВЛЕНО

README заявляет «MIT OR Apache-2.0», но файлов лицензий не было — юридически проект оставался «all rights reserved»: никто не имел права легально использовать/распространять бинарники.

**Сделано:** `LICENSE-MIT`, `LICENSE-APACHE` (полные тексты, © 2026 MFcrychelt and TuffBox contributors), `LICENSE.md` с dual-license-замечанием и оговоркой о сторонних активах (Minecraft © Mojang, лицензии модов).

### 🟡 HARD-7. Поверхность атаки webview — УМЕНЬШЕНО

`withGlobalTauri: true` экспонировал IPC-мост глобально в webview: при любой XSS в webview скрипт получает прямой доступ ко всем 472 командам (файлы, запуск процессов, настройки). Фронтенд глобал не использует (проверено по всем `__TAURI__`-упоминаниям — только исторический комментарий в `themes.ts`; вызовы идут через `@tauri-apps/api`).

**Сделано:** `withGlobalTauri: false` в `tauri.conf.json`. CSP при этом остаётся прежним (script-src 'self').

## Проверено и НЕ является блокером

- **Supabase RLS** — миграции включают row level security по таблицам; anon-ключи в бинарнике — публичные по модели Supabase. Требуется только ops-верификация политик на прод-базе (см. ниже).
- **Секретов в коде приложения нет** — токены хранятся в secret store (`secret_is_set`), GitHub-токены опциональны.
- **Panic-free IPC** — все `unwrap/expect` в `lib.rs` — в тестах; 30 «prod»-unwraps из первичной оценки оказались тестовыми.
- **Остальные места распаковки zip** (`jre.rs`, `mc_install.rs`, `extract_mrpack_overrides`, `extract_mods_only_zip`) — уже имеют traversal-защиту; приведены к единому хелперу только два проблемных.
- **Frontend-гварды CI** (border-radius, bundle budget, lazy views, bridge parity) — прогнаны локально, зелёные; bridge parity: 396 TS ↔ 472 Rust команд, OK.

## Что осталось ДО публичного релиза (вне кода, требуется владелец)

| # | Действие | Почему блокер |
|---|---|---|
| O1 | Выполнить `020_rotate_moderation_secret.sql` на прод-базе и задать секрет ≥16 символов | старый секрет известен из истории git |
| O2 | Подключить tauri-updater (ключ подписи + endpoint) или опубликовать политику «обновление вручную» | у выпущенного приложения нет механизма доставки security-фиксов |
| O3 | Код-сигнинг Windows-бинарника (сертификат) или предупреждение в README о SmartScreen | неподписанный exe → пугающие предупреждения ОС |
| O4 | Ревью RLS-политик прод-базы против миграций | миграции есть, соответствие прода — не проверяемо из репозитория |
| O5 | Применить `docs/patches/0001-build-windows-release-test-gate.patch` (нужен аккаунт с `workflows`-пермиссией) | CI-патч не может быть запушен агентским токеном |
| O6 | Прогнать `cargo test --workspace` + `npm test` после мержа обоих спринтов | в песочнице нет Rust-тулчейна; всё проверено структурно |

## Верификация этого спринта

- tree-sitter-rust: множества ошибок идентичны базовым для `importer.rs` и `lib.rs` (остальные файлы — чисто OK);
- `check-bridge-parity` / `check-border-radius` — зелёные;
- `tauri.conf.json` — валидный JSON, workflow-правка на месте;
- zip2.4.2 `start_file` пишает имя как есть (проверено по исходникам) — malicious-фикстура теста корректна;
- borrow-проверка правок выполнена вручную (move из-под live-заёма устранён через `clone`).

Команды для CI:
```bash
cargo test -p tuffbox-core --lib importer::          # zip-slip тесты
cargo test -p tuffbox-desktop --lib
```
